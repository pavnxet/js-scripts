# NVIDIA GPT-OSS-120B API Proxy

A small Cloudflare Worker that exposes NVIDIA's hosted `openai/gpt-oss-120b` endpoint through an OpenAI-compatible URL.

## Architecture

```text
Your app / MCP / script
        |
        |  OpenAI-compatible request
        v
Cloudflare Worker
        |
        |  NVIDIA_API_KEY (secret)
        v
NVIDIA NIM
        |
        v
openai/gpt-oss-120b
```

The NVIDIA key is kept server-side as a Cloudflare Worker secret and is never sent to clients.

## Endpoints

- `GET /health` — public health check.
- `GET /v1/models` — authenticated model list.
- `POST /v1/chat/completions` — authenticated OpenAI-compatible chat completions proxy.
- Other `/v1/*` requests are proxied to NVIDIA, subject to the same authentication check.

## Deploy

From this directory:

```bash
npm install
npx wrangler login
npx wrangler secret put NVIDIA_API_KEY
npx wrangler secret put API_ACCESS_KEY
npm run deploy
```

`NVIDIA_API_KEY` is the key generated by NVIDIA Build.

`API_ACCESS_KEY` is your own secret. Clients must send it as either:

```http
Authorization: Bearer YOUR_API_ACCESS_KEY
```

or:

```http
X-API-Key: YOUR_API_ACCESS_KEY
```

Do not put either secret in GitHub or in frontend JavaScript.

## Use with the OpenAI Python SDK

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://YOUR-WORKER-DOMAIN/v1",
    api_key="YOUR_API_ACCESS_KEY",
)

response = client.chat.completions.create(
    model="openai/gpt-oss-120b",
    messages=[
        {"role": "user", "content": "Explain the class equation of a finite group."}
    ],
)

print(response.choices[0].message.content)
```

## Use with curl

```bash
curl https://YOUR-WORKER-DOMAIN/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_ACCESS_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "openai/gpt-oss-120b",
    "messages": [
      {"role": "user", "content": "Hello"}
    ],
    "temperature": 0.7,
    "max_tokens": 1024
  }'
```

## Security notes

- Never commit `NVIDIA_API_KEY` or `API_ACCESS_KEY`.
- Keep `API_ACCESS_KEY` enabled for any public deployment; otherwise anyone who discovers the Worker URL could consume your NVIDIA quota.
- NVIDIA remains the upstream provider and controls its own rate limits, availability, and usage policies.
- This Worker does not increase NVIDIA's quota or bypass NVIDIA rate limits.
